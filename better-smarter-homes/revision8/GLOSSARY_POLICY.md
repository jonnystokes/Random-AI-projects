# Revision 5 Glossary Policy

Last updated: 2026-05-08

## Purpose

This file defines how to decide what belongs in the final glossary. It exists so the glossary standard survives compaction.

The glossary must be the last manuscript appendix. Do not finalize or heavily expand the glossary until the chapters and earlier appendices are expanded, researched, and stable.

## Active User Rules

- The glossary goes last.
- The glossary must include every acronym used in the book.
- The selected glossary threshold is Option B: define Level 1 and higher terms.
- Also include Level 0 words when they are construction-related, carry a technical meaning, or would help a curious reader understand the professional and code sections.
- The glossary should help a curious non-builder read professional and code sections without getting lost.
- Do not remove useful source terminology just because it is technical. Define it clearly.
- Definition depth should grow with term difficulty.
- Hard definitions may use the quad-layer intelligence method: start simple, add applied builder meaning, then give the professional definition and related code context.
- The glossary and code index should work together. The glossary has priority on defining words, then it should list related codes, standards, agencies, or code lookup pointers when relevant.
- Add a separate code lookup appendix before the glossary. The code lookup appendix prioritizes finding code topics. The glossary prioritizes understanding words.
- This is part of the Revision 5 new paradigm: the reader can climb from plain language to professional language to code language inside the book.
- Do not use the glossary to add unsupported code, legal, engineering, product, or jurisdiction claims.
- Do not print forms in the book. The glossary may define words such as `form`, `formwork`, or `permit form`, but it must not reproduce form examples.

## Acronym Rule

Every acronym used in the manuscript should appear in the glossary.

When practical, the first use in a chapter should spell out the term first, then give the acronym in parentheses.

Example:

```text
Dynamic Cone Penetrometer (DCP)
```

The glossary entry should include:

- acronym
- full phrase
- plain-language meaning
- where it matters in the build
- related code, standard, agency, or source family if it is code, standard, agency, testing, or professional terminology

## Difficulty Levels

Use these levels to decide the glossary threshold.

| Level | Name | Meaning | Default treatment |
|---|---|---|---|
| 0 | Basic Common | Common everyday words a high-school reader likely knows outside construction | Do not define unless the book uses the word in a special construction meaning |
| 1 | Everyday Building | Common building words a curious reader may have heard but may not fully understand | Define if repeated, important, or easy to confuse |
| 2 | Owner-Builder Technical | Terms an owner-builder needs to act, inspect, buy, request, or document correctly | Define |
| 3 | Professional Trade | Trade, inspection, design, code, or commissioning terms used by builders, inspectors, designers, engineers, or specialty contractors | Define |
| 4 | Specialist / Engineering / Code | Terms that usually require formal code, engineering, testing, manufacturer, or standards context | Define carefully and source-check if the definition makes a hard claim |

## Selected Threshold

The user selected Option B with a useful Level 0 override.

Use this working rule:

- Define every Level 1, Level 2, Level 3, and Level 4 term used in the manuscript.
- Define every acronym used in the manuscript.
- Add Level 0 words when they are construction-related, have a technical definition, or become useful for the reader.

Examples of useful Level 0 or near-Level 0 terms that may deserve entries:

- `wall`, because a wall can mean a structural wall, partition wall, retaining wall, shear wall, foundation wall, masonry wall, concrete wall, or exterior wall assembly.
- `slab`, because a slab can mean a slab-on-grade, topping slab, structural slab, roof slab, basement slab, or insulated slab assembly.
- `form`, because it can mean paperwork or concrete formwork.
- `grade`, because it can mean ground level, slope, elevation, material quality, or code classification depending on context.
- `cover`, because it can mean concrete cover, inspection cover, physical covering, or documentation cover depending on context.

## Threshold Options For Reference

### Option A: Level 2 And Up

Define owner-builder technical terms, professional terms, specialist terms, and all acronyms.

This keeps the glossary tighter, but some curious non-builders may still need outside help for common construction words.

### Option B: Level 1 And Up

Define everyday building terms, owner-builder technical terms, professional terms, specialist terms, and all acronyms.

This is the selected threshold, with selected Level 0 terms added when construction meaning makes them useful.

### Option C: Level 0 Special-Meaning Words Plus Level 1 And Up

Define all construction-relevant terms above basic common language, plus any common word that has a special construction meaning.

This makes the glossary large and friendly. It is the safest choice if the goal is to let a curious non-builder read without searching outside the book.

### Option D: Exhaustive Teaching Glossary

Define almost every construction noun, acronym, code family, test name, system name, material category, and inspection phrase used in the manuscript.

This makes the glossary very large. It may fit the encyclopedic vision, but it will require a careful final audit to avoid duplicated or low-value entries.

## Recommended Working Choice

The selected working choice is Option B with useful Level 0 construction terms:

- Define Level 1 and above.
- Also define Level 0 words when they have a special construction meaning in the book.
- Define every acronym.

This best supports the quad-layer reading model because a curious reader can move from `Simple` into `Professional` and `Code` without leaving the book.

## Definition Depth

Use definition depth based on difficulty.

| Term level | Definition depth |
|---|---|
| Level 0 useful terms | Short plain definition plus the construction-specific meaning |
| Level 1 terms | Simple definition plus a short professional meaning if useful |
| Level 2 terms | Simple definition, applied owner-builder meaning, and common mistake or inspection relevance |
| Level 3 terms | Simple definition, applied meaning, professional definition, failure mode, and related code or standard family when relevant |
| Level 4 terms | Quad-layer explanation when needed: simple explanation, builder/applied explanation, professional definition, related code/standard/source context, and cross-reference to the code lookup appendix |

Do not force all four layers into every glossary entry. Use the expanded form when the word is hard enough that a short definition would not teach the reader.

## Related Code And Code Lookup Rule

The glossary should not replace the code lookup appendix.

For terms with code relevance, the glossary entry should:

1. Define the word first.
2. Explain where it matters in the build.
3. List related code families, standards, agencies, or inspection topics.
4. Point to the code lookup appendix topic when the final appendix exists.

Examples:

- `GFCI`: define the device, explain shock protection, list related electrical code family and inspection relevance.
- `vapor retarder`: define the layer, explain slab/envelope use, list related residential code, energy code, manufacturer instructions, and material standard context if verified.
- `allowable bearing pressure`: define the soil/foundation idea, explain why it affects footing design, list related residential code, geotechnical report, engineering review, and soil testing context.

Do not cite exact code sections in the glossary unless they have been verified and the final code lookup appendix is stable.

## Final Glossary Build Method

Do this after the expanded manuscript is stable:

1. Scan every manuscript chapter for acronyms.
2. Scan every chapter for Level 1 through Level 4 terms.
3. Add Level 0 terms only when they carry a special construction meaning.
4. Include all acronyms.
5. Compare against `revision3/BSHglossary.md`.
6. Compare against `revision2/BSHzapp0AGlossary.md`.
7. Compare against the final code lookup appendix.
8. Remove duplicate entries.
9. Keep definitions plain, active, and useful.
10. Scale definition size to difficulty.
11. Add related code families or lookup pointers where useful.
12. Avoid unsupported hard claims.
13. Verify technical, legal, code, standard, product, and engineering definitions before making them firm.
14. Keep the glossary as the final manuscript appendix.
